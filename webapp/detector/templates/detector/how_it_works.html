Pipeline walkthrough

How Detectra works

From an uploaded file to a REAL / FAKE verdict — every stage the media passes through, in order, and why each one exists.

Detection pipeline
1
Upload & validation Django
The file is checked before anything touches disk: format (.mp4 .avi .mov .mkv for video, .jpg .png for image) and size (100 MB video / 10 MB image by default). If it fails, you get an error immediately — no wasted inference. Valid files are streamed to a temporary path under media/uploads/.
2
Frame extraction OpenCV
For video, up to 150 frames are sampled evenly across the timeline with OpenCV — not just the first few seconds, so a manipulation that only appears mid-clip isn't missed. A single image skips this step; it is treated as one frame.
3
Face detection & crop MTCNN
Each frame is passed to MTCNN (via facenet-pytorch), which locates the face bounding box. Frames with no detectable face are discarded. Detected faces are cropped and resized to 112×112 with bilinear interpolation — the model only ever looks at the face region, not the background.
4
Spatial feature extraction ResNeXt50-32x4d
Every cropped face is run through a pretrained ResNeXt50, fine-tuned on layer4 only (the stem and layers 1–3 stay frozen at their ImageNet weights). Each frame becomes a 2048-dimensional feature vector describing textures, edges, and blending artifacts — the kind of pixel-level inconsistency deepfake generators tend to leave behind.
5
Temporal modelling LSTM
The sequence of 20 sampled feature vectors is fed into a single LSTM layer (hidden size 2048, dropout 0.4). This is where video mode has a real advantage: the LSTM can catch frame-to-frame flicker and temporal inconsistency that a single still frame can never reveal. Output is pooled and passed through a linear layer to 2 classes.
6
Verdict & confidence Softmax
A softmax turns the two output logits into P(Real) and P(Fake). Whichever is higher becomes the label — unless the winning probability is below the 75% confidence threshold, in which case the result is reported as UNCERTAIN rather than forcing a call the model isn't sure about.
7
Grad-CAM explainability layer4 hook
Alongside the verdict, Grad-CAM hooks into ResNeXt's layer4 to compute which pixels most influenced the decision, producing a red/yellow heatmap over the face. This runs per-request via forward/backward hooks that are removed immediately after — it never modifies the trained weights. See the result page for the heatmap grid on any past analysis.
Video vs. single-image mode

Video mode gives the LSTM a genuine sequence of 20 distinct frames to reason over — real temporal signal. Single-image mode repeats the one detected face 20 times to satisfy the model's fixed input shape, so the LSTM sees no actual motion and contributes nothing beyond passing ResNeXt's spatial features through unchanged. Both modes use the exact same trained checkpoint; nothing is retrained or swapped out. Treat image-mode results as a spatial-only estimate, and prefer video whenever a video source is available.
